# 会议返送 / 路由快照发布边界 — 核查证据

本目录的结论可通过仓库根目录的脚本一键复跑：

```
./scripts/verify_return_boundary.sh
```

脚本依次构建并运行单元测试、矩阵竞争并发回归、端到端 demo，并对返送总线的
自身频率幅度做硬性断言；任一步失败即以非零码退出。

## 排查问题

配置连续修改时，会议返送（mix-minus Send 总线）偶发出现远端自身输入。
构造两次相邻路由更新，令音频回调停在“读取边表”与“应用增益”之间，检查处理块
是否混用了两个不同修订。

## 结论：返送频率成分本身正确，缺陷定位在只读边查询的方向边界

### 1. 处理块没有混用修订（返送频率成分前后一致且正确）

`MixerEngine::processBlock` 在块首通过单槽 `ConfigMailbox` 原子换取一个完整冻结
配置，整块只持有同一个 `EffectiveConfig`；相邻两次发布若落在同一块间隙，邮箱只
保留最新修订，旧修订不会被半应用。RT 边表按边键对账（新增淡入、移除淡出一
块），不存在跨修订拼接。

证据（端到端 demo 的 Goertzel 频点幅度，源签名频率 S0..S3）：

- `demo_before_fix.log`：修补前（git HEAD 原始代码，隔离目录构建）
- `demo_after_fix.log` ：修补后（当前工作树代码）
- `demo_return_frequencies.log`：复跑脚本生成的最新证据

两份日志除非确定性的回调耗时外完全一致，矩阵均为 `matrix: PASS`，且：

| 返送总线 | 自身远端签名频点 | 幅度 |
|----------|------------------|------|
| bus 2 (sendA) | S1 (remA) | **0.0000** |
| bus 3 (sendB) | S2 (remB) | **0.0000** |

即返送始终不含自身输入。因此按任务约定，未改动 DSP/邮箱/发布逻辑，而是加强
路由快照发布附近的边界回归。

### 2. 实际修正：`RoutingGraph::findEdge` 的反向回退缺陷

`findedge_before_after.log` 给出同一探针在修补前后的输出。原始实现对查不到的
`(from,to)` 再以 `(to,from)` 反向回退匹配，导致一个有向图中并不存在的
bus→source 查询回显一条无关的 source→bus 边而误报“边存在”。这是控制侧只读
/UI presence 检查的边界缺陷（不在音频路径，快照发布直接遍历边表，故不影响
返送频率）。修补为严格按 `(from,to)` 精确查找，保持有向语义。

### 3. 矩阵竞争回归（不得用默认结果遮住失败）

`matrix_competition_regression.log` 来自 `tests/regression_concurrency.cpp`，
期望矩阵由“真正驱动每个块的那个冻结配置”重建，再与实际渲染音频的 Goertzel
检测逐格比对，检测到/期望不一致即计失败，因此不存在默认通过掩盖失败的可能。
覆盖：

1. 跳过中间修订的块边界（相邻两更新落在一块间隙）
2. 快速编辑下逐块矩阵与单一修订的一致性
3. 负载下反馈环拒绝规则保持不变（含真实可闭合环路）
4. 静音 + 断流并发浸泡，返送自身泄漏为零
5. 邮箱最新代语义（只交付最新、每代至多一次、取后为空、旧快照保持不可变）
6. 每个渲染块钉在单一代次（代次序列单调不回退）
7. `findEdge` 严格有向查询边界

`unit_tests.log` 为既有单元测试结果（含反馈环拒绝、mix-minus、冻结快照一致性
等），修补后 1572 项全部通过。
